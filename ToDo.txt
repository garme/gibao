### 🧠 1. Com suporte do Analisador Semântico (`semantic.py`)

**Inlay Hints (Dicas Embutidas "Fantasmas")**
* **O que faz:** Um recurso muito popular no VS Code e no Rust. Quando você chama uma função como `calcular(10, 20);`, a IDE injeta textos cinzas, pequenos e não-editáveis antes dos números, mostrando o nome dos parâmetros: `calcular(x: 10, y: 20);`.
* **Como implementar:** O Parser lê a chamada da função e o Semântico busca a assinatura dela. O Tkinter permite inserir "widgets" ou textos com tags especiais dentro do `Text` que não afetam o código real.

### ✂️ 3. Com suporte do Pré-processador (`preprocess.py`)

**Visualizador de Compilação Condicional (Fade Out)**
* **O que faz:** Deixa "cinza" ou "transparente" blocos de código que não serão compilados.
* **Como implementar:** Se o aluno escrever um bloco `#ifdef DEBUG`, e não houver nenhum `#define DEBUG` no código, o Pré-processador sabe que aquele bloco será ignorado. A IDE pega essas coordenadas do pré-processador e pinta aquele bloco inteiro com uma cor cinza-escuro, indicando visualmente que aquele trecho está desativado.

**Expansão de Macro ao Passar o Mouse (Macro Peek)**
* **O que faz:** Quando o usuário passa o mouse sobre uma macro complexa, como `MAX(a, b)`, o tooltip não mostra apenas a definição, mas mostra **como o código ficará depois de expandido**, substituindo `a` e `b` pelos valores reais daquela linha.

### 🎨 Categoria 3: Experiência Profissional (UX/UI)

**5. Minimapa de Código (Minimap)**
O recurso mais icônico de editores modernos (VS Code, Sublime).
* **Como seria:** Uma barra vertical fina no canto direito do editor mostrando uma miniatura do código inteiro.
* **Destaques:** Permite que o usuário role arquivos gigantes (como bibliotecas com 1000 linhas) de forma extremamente rápida e visual, sabendo pelo formato da miniatura onde estão os blocos de funções.

**6. Navegação por *Breadcrumbs* (Migalhas de Pão)**
* **Como seria:** Uma barrinha estreita logo acima da área de texto mostrando o escopo atual do cursor.
* **Destaques:** Se o cursor está dentro de um laço `for` na função `matriz`, a barra exibe: `📂 workspace > 📄 main.c > ⚙️ matriz() > ➿ for`. Clicar em qualquer um desses itens abre um menu rápido para pular para outra função.

**7. Painel Nativo de Git / Diff Viewer**
* **Como seria:** Adicionar uma aba na barra lateral (junto com Explorador e Estrutura) dedicada ao Git.
* **Destaques:** Mostra quais arquivos foram Modificados (M) ou Adicionados (A). Clicar em um arquivo abre um **Diff Viewer** (tela dividida que mostra o código antigo em vermelho à esquerda e o novo em verde à direita).

### 🛠️ Categoria 4: Produtividade e Refatoração

**8. Extrair Função (Extract Method)**
Um recurso poderoso de refatoração.
* **Como seria:** O usuário seleciona 10 linhas de código dentro do `main()`, clica com o botão direito e escolhe "Extrair Função".
* **Destaques:** A IDE pede o nome da nova função, recorta o texto, cria a função nova acima do `main()` e substitui as 10 linhas por uma chamada simples: `nova_funcao();`.

**9. Gerenciador Visual de Snippets**
Em vez de depender de você adicionar *snippets* hardcoded no dicionário `CODE_SNIPPETS`.
* **Como seria:** Uma tela de configurações na IDE onde o próprio usuário pode criar seus blocos de código personalizados, dar um nome (ex: `meu_loop`) e salvá-los no `.hist` ou num `.json` separado, para que apareçam automaticamente no Auto-complete dele.

### 1. Painel Nativo de Controle de Versão (Integração Git)
Em vez de ter que abrir o terminal para gerenciar o código, podemos criar uma aba no painel lateral (junto com o Explorador e a Estrutura) dedicada ao Git.
* **O que faz:** Lê o status do repositório local e lista visualmente os arquivos modificados (M), adicionados (A) ou deletados (D) com cores diferentes.
* **Diferencial:** Você poderia escrever a mensagem de *commit* e fazer o *push* para o GitHub diretamente por uma interface gráfica simples na IDE. É um excelente próximo passo arquitetural para escalar projetos.

### 5. Navegação por *Breadcrumbs* (Migalhas de Pão)
Para não se perder em arquivos longos, podemos adicionar uma barra estreita logo abaixo das abas de edição.
* **O que faz:** Mostra exatamente o escopo onde o cursor está no momento. Exemplo: Se o cursor estiver dentro de um `while` na função `calcular()`, a barrinha mostra: `workspace > math.c > calcular() > loop while`.
* **Diferencial:** Clicar em qualquer uma dessas palavras abre um menu suspenso para pular rapidamente para outra função do mesmo arquivo.

### 6. Visualizador de Execução (Modo Debugger Integrado)
Já que a IDE gera o código Assembly para a arquitetura CARIRI, o ápice da ferramenta seria não apenas compilar, mas "ver rodando".
* **O que faz:** Uma interface que permita dar um "Step In" (executar linha por linha) do Assembly gerado, mostrando em um painel lateral os valores atuais dos Registradores e da Memória mudando em tempo real.
* **Diferencial:** Fecha o ciclo completo: escrever em C -> compilar -> executar -> depurar, tudo sem sair da mesma janela.

### 3. Debugging (Depuração) Visual
* **Breakpoints (Pontos de Parada):** Clicar ao lado do número da linha para adicionar uma bolinha vermelha `🔴`, indicando onde o simulador deve pausar a execução.
* **Inspeção de Variáveis (Watch Variables):** Um painel lateral que mostra o valor atual das variáveis na memória (RAM) enquanto o código roda passo a passo.
* **Pilha de Chamadas (Call Stack):** Um painel mostrando a ordem em que as funções foram chamadas até o ponto de erro ou pausa.
* **Visualizador de Memória/Hex Dump:** Como estamos lidando com um compilador para a arquitetura CARIRI (Assembly), uma janela mostrando o mapa de memória cru (Hexadecimal) e os Registradores da CPU é um recurso profissional vital.


### 🌟 Categoria 1: O "Killer Feature" (Execução e Análise)

**1. Emulador Visual Integrado (Visual Debugger)**
Já que a sua IDE gera o código Assembly (CARIRI), o passo supremo é permitir que o aluno **veja o código rodando**.
* **Como seria:** Um painel lateral ou inferior que funciona como um emulador passo a passo (*Step Into, Step Over*).
* **Destaques:** Uma tabela atualizada em tempo real mostrando o estado dos Registradores (PC, SP, acumuladores) e um "Hex Dump" da Memória RAM. O aluno clica em "Próximo Passo" no Assembly e vê a variável mudando na memória.

**2. Grafo de Chamadas (Call Graph View)**
Entender o fluxo de um programa C complexo é difícil para iniciantes.
* **Como seria:** Uma aba que gera uma representação visual (uma teia/árvore) de quais funções chamam quais. 
* **Destaques:** Clicando no nó `main()`, ele expande ramificações mostrando setas para `soma()`, `printint()`, etc. Excelente para visualizar gargalos ou recursões.
